## Post Content

You're writing Python every day and still losing hours to problems Python already solved.

Most developers write three times more code than they need to. Not because they're bad engineers — because they never sat with the standard library long enough to know what's already there.

Here's what changed my workflow:

1. `pathlib` instead of `os.path` — your file manipulation code just became readable
2. `dataclasses` instead of boilerplate `__init__` methods — 15 lines becomes 3
3. `contextlib.suppress` instead of try/except blocks for ignored errors — stop writing 4-line blocks for one-liner intent 🐍
4. `functools.cache` instead of writing your own memoization — it's one decorator, not 20 lines
5. Generator expressions instead of list comprehensions when you're just iterating — stop building the list you immediately loop through

The deeper issue: Python rewards the people who know what's built in. The language has been around for 30 years — a lot of the "clever" code you're writing already exists, tested, and maintained.

Rule: before you write a utility function, search the standard library for 2 minutes. The 2 minutes pays for itself within a day. 💡
